## Shipped-source gameplay promise and acquisition

This is an integration mod, **not a new block, item, recipe, or GUI**. Its `ModMain`, `SupportPreviewClient`, `SupportPreviewServer`, `RbpSupportPreviewAdapter` and RotaVision mixins implement an advisory, server-evaluated support tint on RotaVision's existing placement ghost for block items. The client observes the main-hand placement preview, requests an evaluation at most every 250 ms (500 ms refresh for unchanged focus), caches the server response for up to 750 ms, and shades vanilla-invalid placements red, supported placements teal, predicted fall/crush amber, and unmanaged/unknown placements neutral white (`PreviewTint`). The server reconstructs placement using the actual held item, hit and rotation, checks reach (8 blocks) and loaded chunks, models bed/door/double-height companion states, and evaluates the candidate against a virtual RBP overlay with read-only task manager. This does **not** authorize placement or promise the real subsequent physics simulation will match every prediction: errors and unsupported/unmodeled configurations return UNKNOWN. Only the exact compatible RotaVision 1.0.2, RBP 1.0.0 and Realistic Physics 1.0.1 versions are evaluated (`SupportPreviewVersions`); `mods.toml` also declares mandatory dependencies. The client mixin affects RotaVision's renderer, not a standalone preview GUI.

Acquisition reference for playtest recipes/roots: use existing vanilla/pack **placeable block items** (e.g. stone, sand, oak stairs, red bed, oak door, sunflower) and RotaVision's existing ghost/rotation controls. `src/main/resources` contains no recipes or loot tables and this repo registers no new items or blocks; there is no independent crafting root or mod GUI to acquire. Test each representative item via its *pack-installed* acquisition path rather than asserting this mod supplies it. Bed, door, and double-height placements are special modeled cases; unsupported custom BlockItem subclasses may deliberately fall back to UNKNOWN.
